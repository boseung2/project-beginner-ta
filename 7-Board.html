0. 프로젝트 세팅

먼저 터미널에서 node -v로 버전을 확인합니다. (20.19 이상)

npm create vite@latest my-board -- --template react-ts

cd my-board

npm install

npm run dev

첫 줄 실행 중 질문이 나오면: Which linter to use? → 그대로 Enter · Install with npm and start now? → No 고르고 아래 명령을 직접 칩니다.

VS Code 자동 import: VS Code에서는 my-board 폴더를 엽니다. (파일 → 폴더 열기) 확장(Extensions)에서 Auto Import - ES6, TS, JSX, TSX를 설치합니다.

  • useState, PostList처럼 다른 파일에 있는 이름은 입력하다가 자동완성 목록에서 고르면 맨 위에 import가 붙습니다.
  • 이미 빨간 줄이 생겼으면 그 위에 커서를 두고 Cmd+. (Windows Ctrl+.) → Add import를 고릅니다.

실습 전에 준비할 것은 두 가지입니다.

  1. public/posts.json 파일을 만들고 아래 글 3개를 붙여 넣는다. (미리 저장해 둔 데이터)
  2. src 안에 components 폴더를 만든다.

나머지 파일은 각 Step 맨 앞의 🧱 시작 템플릿을 붙여 넣어 만듭니다. (Step 1: types.ts · App.tsx · PostList.tsx · PostItem.tsx, Step 2: PostFormModal.tsx)

나머지 파일은 고치지 않습니다.

파일어떻게

src/index.css그대로 둔다. 6주차처럼 바꾸지 않아도 됩니다. 스타일은 각 컴포넌트 안 styles에 있습니다.
src/App.css쓰지 않음 (새 App.tsx가 불러오지 않음). 지워도 되고 둬도 됩니다.
src/assets/쓰지 않음 (Vite 첫 화면의 그림). 지워도 되고 둬도 됩니다.

0-2. 컴포넌트 기본 구조

컴포넌트는 화면 한 조각을 만드는 함수입니다. 실습의 컴포넌트 파일은 모두 아래와 같은 순서로 되어 있습니다. 좋아요 버튼 하나로 보겠습니다.

부분하는 일
① importuseState 같은 기능, 다른 파일의 컴포넌트 · 타입을 가져온다
② function LikeButton()컴포넌트 이름은 대문자로 시작 (파일 이름과 같게)
③ 상태 · 함수return 위에서 useState, 버튼을 눌렀을 때 할 일 등을 준비
④ return ( ... )화면에 그릴 내용 (JSX). 태그는 하나로 감싼다
⑤ styles이 컴포넌트에서 쓰는 스타일
⑥ export default다른 파일에서 쓸 수 있게 내보낸다

0-3. import와 export

컴포넌트를 파일마다 나누면, 파일끼리 export(내보내기)와 import(가져오기)로 연결합니다.

App에서 가져온 LikeButton을 태그처럼 <LikeButton />로 씁니다. 두 번 쓰면 버튼이 두 개 생기고, 각자 자기 count를 가집니다.

내보내는 쪽가져오는 쪽
export default LikeButton;
(파일에 하나, 보통 컴포넌트)		import LikeButton from "./components/LikeButton";
export interface Post { ... }
(타입 앞에 export)		import type { Post } from "./types";
  • 주소는 지금 파일 기준입니다. ./는 같은 폴더, ../는 한 칸 위 폴더입니다. (components 안의 파일에서 types.ts는 ../types)
  • 파일 끝의 .tsx, .ts는 쓰지 않습니다.
  • import를 직접 치기 어려우면 위의 VS Code 자동 import를 씁니다.

0-4. 컴포넌트 연결과 props

컴포넌트 안에서 다른 컴포넌트를 가져다 쓰면 부모와 자식이 됩니다. 파일은 모두 따로 있고, 부모 파일이 자식 파일을 import 해서 태그로 씁니다.

부모가 자식에게 값을 넘길 때 쓰는 것이 props입니다. 태그에 이름={값}으로 넘기고, 자식은 함수의 매개변수로 받습니다.

<Hello name="민수" />로 넘기면 Hello는 { name }으로 받습니다. 받는 쪽에는 { name: string }처럼 타입도 적습니다. 같은 컴포넌트를 값만 바꿔 여러 번 쓸 수 있습니다.

게시판의 파일 4개는 이렇게 연결됩니다. 화살표 위 글자가 넘기는 props입니다.

  • PostFormModal에는 닫기 · 추가 함수를 넘깁니다. (Step 2 · 3)

1-1. 게시글 하나를 상태로

interface Post는 types.ts에 한 번만 쓰고, 쓰는 파일에서 import type { Post } from "./types";로 가져옵니다.

1-2. 게시글 리스트를 상태로 + map

map으로 그릴 때 key에는 글마다 다른 값(id)을 넣습니다. React가 어느 글이 바뀌었는지 구분하는 이름표입니다.

1-3. 파일에서 리스트 불러오기 (useEffect + fetch)

fetch(주소)는 파일이나 서버에 있는 데이터를 가져옵니다. 가져오는 데 시간이 걸리기 때문에, 다 가져온 뒤에 할 일을 .then으로 이어 씁니다.

fetch("/posts.json")                  ① posts.json 파일을 요청
  .then((res) => res.json())          ② 받은 응답(res)을 데이터(배열)로 바꾸기
  .then((data) => setPosts(data));    ③ 바꾼 데이터를 state에 넣기 → 화면에 그려짐
  • .then 안의 함수는 앞 단계가 끝나면 실행되고, 앞 단계의 결과를 받습니다. ②의 결과가 ③의 data로 들어갑니다.
  • fetch는 useEffect(..., []) 안에 둡니다. 밖에 두면 화면을 그릴 때마다 다시 불러와서 끝없이 반복됩니다.

"/posts.json"은 public/posts.json입니다. 의존성 []라서 처음 한 번만 불러옵니다.

1-4. 컴포넌트로 나누기 + props

글 하나를 그리는 PostItem을 components 폴더의 다른 파일로 만들고, 목록 쪽에서 import 해서 씁니다.

부모가 <PostItem post={post} />로 넘기면, 자식은 { post }로 받습니다. components 안의 파일에서 types는 한 칸 위라서 "../types"입니다. 실습의 PostList · PostItem도 이렇게 파일을 따로 만듭니다.

1-5. 열고 닫기

모달도 같은 원리입니다. isModalOpen이 true일 때만 모달을 그립니다.

1-6. 입력 폼으로 새 글 만들기

{ id: Date.now(), ...form }: 입력값 객체를 복사하고 id를 붙여 새 글을 만듭니다. Date.now()는 지금 시각(숫자)이라 글마다 다릅니다.

1-7. 리스트에 하나 추가하기

[newPost, ...posts]: 새 글 + 기존 글을 펼쳐 넣은 새 배열입니다. state는 새 값으로 바꿔야 화면이 다시 그려집니다.

1-8. 함수를 props로 넘기기 (자식 → 부모)

목록(state)은 부모가 갖고, 자식은 props로 받은 함수를 불러 "이 글을 추가해 줘"라고 알립니다. 실습에서는 글쓰기 모달(자식)이 App(부모)에게 onAdd(newPost)로 새 글을 보냅니다.

1-9. 새로고침해도 남기기 (localStorage)

localStorage에는 글자만 저장됩니다. 배열 · 객체는 JSON.stringify로 글자로 바꿔 저장하고, 꺼낼 때 JSON.parse로 되돌립니다. [처음부터]가 새로고침입니다.
