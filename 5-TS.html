5. TypeScript

초급프로젝트 TA SESSION · 1~7장에서 TypeScript 문법을 보고, 8장에서 4주차 할 일 목록을 내 컴퓨터에서 TS로 옮깁니다. TS 예제는 오른쪽에 타입 검사(실행 전에 찾은 오류)와 콘솔(실행 결과)이 함께 나옵니다.

1. TypeScript — 실행 전에 검사하는 JS

TypeScript(TS)는 JS에 타입을 적을 수 있게 한 언어입니다. 코드를 실행하기 전에 검사해서, 타입이 맞지 않는 곳을 미리 빨간 줄로 알려 줍니다.

1-1. TS 프로젝트 만들기 — 내 컴퓨터에서

TS를 쓰려면 먼저 내 컴퓨터에 TS 프로젝트(TS 도구가 설치된 폴더)를 만듭니다. 여기서 만드는 ts-practice에서 이 페이지의 예제를 모두 돌립니다.

먼저 nodejs.org에서 LTS 버전을 설치하고, VS Code 터미널(Ctrl+`)에서 node -v로 버전이 나오는지 확인합니다.

  1. ts-practice 폴더를 만들고 VS Code로 연다.
  2. 터미널에서 npm init -y를 실행한다. package.json이 생긴다.
  3. 터미널에서 npm install typescript@5.9 --save-dev를 실행한다. node_modules 폴더에 tsc(TS를 JS로 바꾸는 도구)가 설치된다.
  4. 폴더에 tsconfig.json을 만들고 아래 내용을 넣는다.
{
  "compilerOptions": {
    "target": "ES2020",
    "strict": true
  }
}
ts-practice/
├─ package.json       ← npm init -y가 만듦
├─ package-lock.json  ← npm install이 만듦
├─ node_modules/      ← npm install이 만듦 (tsc가 여기 있음)
└─ tsconfig.json      ← 직접 만듦
프로젝트 이름 · 설치한 도구 목록package.jsondevDependencies에 typescript가 적힘. 직접 고칠 일은 없음
설치한 도구의 실제 파일node_modules/지워도 npm install로 다시 생김. 남에게 줄 때는 빼고 줌
tsc 설정tsconfig.jsontarget: 어느 버전의 JS로 바꿀지 · strict: 엄격하게 검사
코드를 쓰는 파일.ts직접 만듦. 빨간 줄은 여기서 고침
tsc가 만든 결과.js고치지 않음. 고쳐도 다음 npx tsc 때 덮어씀

1-2. 먼저 보기 — 타입이 없을 때와 있을 때

같은 덧셈 함수를 타입 없이, 그리고 타입을 붙여 씁니다. 오른쪽 타입 검사에는 TS가 실행 전에 찾은 빨간 줄이 나옵니다.

타입을 안 줌function plus(a, b)a, b가 무엇인지 몰라 빨간 줄 (implicitly has an 'any' type)
타입을 줌function addNum(a: number, b: number)숫자 자리에 "1"을 넣으면 빨간 줄
JS로 실행하면plus("1", 2)오류 없이 12 — 글자 "1"에 2가 이어 붙음

입력칸의 값(input.value)은 늘 글자입니다. 이런 실수를 TS는 실행하기 전에 빨간 줄로 알려 줍니다.

이 예제를 ts-practice에서 직접 돌려 봅니다.

  1. ts-practice에 새 파일 chap1-add.ts를 만들고, 위 예제를 [복사]해 붙인다. VS Code에 빨간 줄이 보인다.
  2. 터미널에서 npx tsc를 실행한다. 오류 목록이 나오고 chap1-add.js가 생긴다.
  3. 터미널에서 node chap1-add.js를 실행한다. 3, 12, 12가 나온다.
ts-practice/
├─ …                  ← 1-1에서 만든 것
├─ chap1-add.ts          ← 직접 만들고 예제를 붙여 넣음
└─ chap1-add.js          ← npx tsc가 만듦

1-3. 실행 흐름 — .ts → .js

브라우저와 node는 TS를 바로 실행하지 못합니다. tsc가 검사한 뒤 타입을 지운 JS로 바꾸고, 그 JS를 실행합니다.

chap1-add.ts  →  tsc: 타입 검사 + 타입 지우기  →  chap1-add.js  →  브라우저 · node에서 실행
              (틀리면 빨간 줄)

npx tsc는 폴더 안 .ts 파일을 모두 검사하고 바꿉니다. 오류가 있어도 .js는 만들어지므로 1-2처럼 빨간 줄이 있어도 실행은 됩니다. 터미널의 오류는 chap1-add.ts:2:15(파일:줄:칸)처럼 영어로 나옵니다 — 이 페이지 타입 검사 칸의 회색 영어 줄과 같은 문장입니다. npx tsc -w를 켜 두면 저장할 때마다 다시 바꿉니다(끄기: Ctrl+C).

2. 기본 타입

변수 이름 뒤에 : 타입을 붙입니다. 이 장부터 예제 오른쪽에는 타입 검사와 콘솔이 함께 나옵니다. 일부러 틀린 줄은 맨 아래에 두었습니다.

let 이름: 타입 = 값;
예)  let age: number = 21;

예제는 1-1에서 만든 ts-practice에서 직접 돌려 봅니다. 예제 이름 옆의 파일 이름 그대로 저장하면 됩니다.

[복사] → chap2-types.ts에 붙이기 → npx tsc → node chap2-types.js

숫자 · 문자열 · 참거짓number · string · booleanC의 int · double을 모두 number로
배열number[]Array<number>로도 씀

둘 다 "아무 값이나" 담지만, unknown은 확인한 뒤에만 쓸 수 있고 any는 검사를 아예 끕니다.

이름 붙인 상수 묶음enum Color { Red, Green, Blue }Color.Red는 0, Color.Green은 1 …

3. 함수 — 매개변수와 반환 타입

매개변수 뒤에 타입을, 괄호 뒤에 돌려줄 값의 타입을 적습니다. 타입이나 개수가 다르게 부르면 빨간 줄이 생깁니다.

function add(a: number, b: number): number { … }
const double = (n: number): number => n * 2;

4. 객체 — interface · type

객체에 어떤 속성이 어떤 타입으로 있어야 하는지 모양을 정해 두고, 변수와 매개변수에 씁니다. 속성이 빠지거나 타입이 다르면 빨간 줄이 생깁니다.

4-1. interface · type으로 모양 정하기

모양 정하기interface User { name: string; }객체의 속성과 타입
있어도 없어도 됨isStudent?: boolean선택 속성
읽기만readonly id: number처음 넣은 뒤에는 바꿀 수 없음
넓히기interface Student extends UserUser 속성 + major
이름 붙이기type Product = { … }객체 말고 유니언 등 무엇에나 이름을 붙일 수 있음
합치기Product & { discount: number }두 모양을 모두 가진 타입
키 이름을 미리 모를 때{ [key: string]: number }어떤 키든 값은 number

객체 모양은 interface와 type 어느 쪽으로 정해도 됩니다. 프로젝트 안에서는 한쪽으로 맞춥니다.

5. DOM과 함께 쓰기 — null · 요소 타입 · 좁히기

3주차 코드를 TS로 옮기면 가장 먼저 만나는 빨간 줄입니다. 8장 실습에서 그대로 씁니다.

5-1. querySelector가 주는 타입

querySelector는 맞는 요소가 없으면 null을 돌려줍니다. 또 "#notice-input"만 보고는 input인지 알 수 없어서 Element로 보고, Element에는 value가 없습니다.

어떤 요소인지querySelector<HTMLInputElement>("#id")그래야 .value를 쓸 수 있음
꼭 있다고 약속querySelector(…)!null이 아니라고 봄. 실제로 없으면 실행할 때 null 오류
확인하고 쓰기if (box) { … }if 안에서는 null이 아님(좁히기)
자주 쓰는 요소 타입HTMLInputElement · HTMLButtonElementinput · button. ul은 HTMLUListElement, li는 HTMLLIElement
태그로 찾거나 만들 때querySelector("li") · createElement("li")태그 이름이 있으면 타입을 알아서 앎

이 예제는 ts-practice에서 npx tsc까지만 해 봅니다. node chap5-dom.js로 실행하면 document is not defined가 나옵니다 — document는 브라우저에만 있기 때문입니다. 브라우저에서 돌리는 것은 8장 실습에서 합니다.

5-2. 좁히기와 단언 — typeof · as

유니언 값은 typeof로 확인하면 if 안에서 타입이 하나로 좁혀집니다. as는 검사를 건너뛰고 "이 타입이라고 치자"고 말하는 것이라, 틀리면 빨간 줄 없이 실행할 때 터집니다.

좁히기if (typeof a === "number")if 안에서 a는 number
타입 단언a as number검사를 건너뜀. 꼭 필요할 때만
null 아님 단언값!5-1의 !와 같음

as와 !는 TS에게 "내가 책임진다"고 말하는 것입니다. 타입 검사가 통과해도 실행할 때 오류가 날 수 있습니다.

6. 클래스

JS 클래스에 속성 타입과 접근 제어자(public · private)를 더합니다. 2분반(디자인 패턴)에서 다시 나옵니다.

6-1. class · extends · private · implements

클래스와 생성자class Person { constructor(…) { … } }new Person("홍길동", 21)로 만듦
상속class Developer extends Person생성자 첫 줄에서 super(…)로 부모 생성자 호출
접근 제어자public · private · protected어디서나 · 클래스 안에서만 · 자식 클래스까지

약속 지키기class Circle implements Shapeinterface의 메서드를 모두 만들어야 함
추상 클래스abstract class Shape { abstract area(): number; }new로 못 만들고 상속해서만 씀

private은 TS 검사에서만 막습니다. 마지막 줄도 실행은 되어 21이 찍힙니다. JS에서 정말 감추려면 #age처럼 씁니다.

8. 실습: 할 일 목록을 TS로 — 새 프로젝트에서

4주차에 만든 todo.html의 JS를 TS로 옮깁니다. ts-practice와 따로 새 프로젝트를 1-1과 같은 순서로 만듭니다. 1~3부까지 하면 완료입니다.

8-1. 완성된 폴더 모양

todo-ts/
├─ package.json       ← npm init -y가 만듦
├─ package-lock.json  ← npm install이 만듦
├─ node_modules/      ← npm install이 만듦
├─ tsconfig.json      ← 1-1과 같은 내용
├─ todo.html          ← 4주차 파일
├─ main.ts            ← script 안 코드를 옮김
└─ main.js            ← npx tsc가 만듦

ts-practice에 넣지 않는 이유: 한 프로젝트의 .ts 파일들은 이름을 같이 씁니다. 5-1 예제에도 input · list가 있어서, 같은 이름을 쓰면 "다시 선언할 수 없습니다" 빨간 줄이 납니다.

1부 · 프로젝트 만들기

  1. todo-ts 폴더를 만들고 VS Code로 연다.
  2. 1-1의 2~4번을 그대로 한다: npm init -y → npm install typescript@5.9 --save-dev → tsconfig.json 만들기

2부 · TS 파일로 옮기기

  1. todo.html을 todo-ts 폴더에 복사한다.
  2. main.ts를 만들고 todo.html의 script 안 코드를 옮긴다.
  3. todo.html의 script를 <script src="main.js"></script>로 바꾼다. 자리(body 맨 끝)는 그대로 둔다.
4주차 todo.html이 없다면 — 펼쳐서 복사하기

4주차 실습 1~4부를 마친 코드입니다. [복사]해 todo-ts 폴더에 todo.html로 저장하고 위 2번부터 하면 됩니다.

3부 · 빨간 줄 고치고 실행하기

  1. main.ts의 빨간 줄을 고친다. (5-1: <HTMLInputElement> · ! / 함수 매개변수는 3장처럼 타입을 적기 / 숫자를 textContent에 넣을 때는 String(count))
  2. 터미널에서 npx tsc를 실행한다. main.js가 생긴다.
  3. Live Server로 todo.html을 열어 동작을 확인한다.
  4. npx tsc -w를 켜 두면 저장할 때마다 다시 변환된다.

완료 확인

  • main.ts에 빨간 줄 없음
  • npx tsc로 main.js가 만들어짐
  • todo.html에서 추가 · 줄 긋기가 4주차와 똑같이 동작함
  • 콘솔에 빨간 줄 없음

main.ts에서 바꾼 줄과 그 이유를 설명하면 먼저 나가도 됩니다.
